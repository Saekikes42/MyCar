# SQLite

Файл по умолчанию: `backend/data/mycar.db`. Путь вычисляется относительно репозитория, поэтому не зависит от текущего рабочего каталога сервера. Пользовательский `--db` может задавать другой путь.

| Таблица | Назначение |
| --- | --- |
| `users` | Профиль, уникальный email без учёта регистра, хеш пароля |
| `sessions` | Хеш токена, владелец, срок действия |
| `cars` | Марка, модель, демонстрационное количество |
| `configurations` | Автомобиль, год, цвет, комплектация, цена, изображение |
| `cart_items` | Пользователь, комплектация и количество 1–99 |
| `orders` | Заявка и снимок выбранного товара на момент оформления |

Внешние ключи включаются для каждого соединения. Для конкурентных чтений используется WAL. Денежные значения каталога хранятся целыми копейками (`price_cents`); API возвращает рубли. `CartItem.id` и `OrderRequest.itemId` означают ID комплектации, `Car.id` означает ID автомобиля.

Цена и описание товара берутся сервером из каталога, имя и email клиента — из профиля. Клиентские значения этих полей не определяют цену или владельца заказа. Оформление и удаление выбранной позиции корзины выполняются в одной транзакции с `BEGIN IMMEDIATE`, чтобы параллельные запросы не создавали две заявки на одну позицию. Снимок `item_json` сохраняет исторические данные, даже если каталог позже изменится. Другие позиции корзины сохраняются.

`schema.sql` задаёт начальную версию схемы (`PRAGMA user_version = 1`). Инициализация повторяема: существующие строки не заменяются, тестовый каталог не дублируется. Другие версии схемы отклоняются. Миграции для последующих изменений пока не реализованы: при развитии проекта их нужно добавить явно.

Для просмотра базы можно использовать любой SQLite-клиент. Для чистой демонстрации запустите сервер с новым `--db`; существующую базу удалять не требуется. Для резервной копии остановите сервер и скопируйте файл базы. Файлы `.db`, `.db-wal`, `.db-shm` и содержимое `backend/data` исключены из Git.
