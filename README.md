# MyCar

Учебное Android-приложение автосалона на Kotlin. Первую версию я разработал в 2025 году; в 2026 году проект подготовлен для портфолио: упорядочены пакеты, восстановлен локальный API с SQLite, добавлены проверки серверных сценариев и инструкция запуска.

## Возможности

- Регистрация, вход, выход и редактирование профиля.
- Каталог автомобилей с изображениями из локального сервера.
- Выбор года и комплектации с актуальной ценой.
- Корзина и оформление заявки на выбранный автомобиль.
- История заявок с поиском и фильтрами по статусу.

## Стек и структура

Android: Kotlin, XML layouts, AppCompat, Material Components, OkHttp, Gson, Glide, Gradle Kotlin DSL. На экране комплектаций используется View Binding; остальные экраны сохраняют исходный подход с `findViewById`.

Сервер: Python 3.10+ и SQLite, без внешних Python-зависимостей. Android работает с данными через HTTP API.

```text
app/src/main/java/com/example/mycardemo/
├── ui/             # Экраны и общая нижняя навигация
├── api/            # HTTP-запросы и адреса изображений
├── data/           # Локальные данные сессии
├── models/         # Модели запросов и ответов
└── MyCarApplication.kt
backend/
├── server.py       # HTTP-маршруты и запуск
├── service.py      # Валидация и операции с данными
├── database.py     # Создание базы и тестового каталога
├── security.py     # Хеширование паролей и токенов
├── schema.sql      # Схема SQLite
└── tests/          # Интеграционные HTTP-тесты
```

## Быстрый запуск

### 1. Сервер и база

Из корня проекта:

```shell
python -m backend.server
```

На Windows вместо `python` также можно использовать `py -3`. Сервер запускается на `http://127.0.0.1:5114`. Проверка: откройте [health](http://127.0.0.1:5114/health) или [каталог](http://127.0.0.1:5114/api/car).

При первом запуске создаётся `backend/data/mycar.db` и каталог из трёх учебных автомобилей, двух годов и трёх комплектаций. Цены демонстрационные. Изображения берутся из ресурсов этого репозитория. Повторный запуск сохраняет пользователей, корзины и заявки. Аккаунты не создаются заранее: зарегистрируйтесь в приложении. Пример пароля, соответствующего правилам формы: `Study2025!`; дата рождения: `2000-01-15`.

Другой путь к базе или порт:

```shell
python -m backend.server --db backend/data/another-demo.db --port 5114
```

### 2. Android-приложение

1. Откройте корень проекта в Android Studio.
2. Используйте Gradle JDK 17 или новее (подходит встроенный JDK Android Studio).
3. Установите Android SDK Platform 36 и выполните Gradle Sync.
4. Запустите `app` на эмуляторе с Android 7.0 / API 24 или новее.
5. Оставьте сервер работающим, зарегистрируйтесь и войдите.

По умолчанию используется `http://10.0.2.2:5114/`: Android Emulator обращается по этому адресу к компьютеру разработчика.

Для физического устройства по USB:

```shell
adb reverse tcp:5114 tcp:5114
```

В локальный `~/.gradle/gradle.properties` добавьте `API_BASE_URL=http://127.0.0.1:5114/`, затем пересоберите приложение. Для эмулятора удалите эту настройку либо верните `http://10.0.2.2:5114/`. Адрес также можно передать при сборке:

```shell
./gradlew assembleDebug -PAPI_BASE_URL=http://127.0.0.1:5114/
```

HTTP разрешён в debug-сборке. Release-сборка требует сервер с HTTPS и соответствующий `API_BASE_URL`.

## Проверки

```shell
python -m unittest discover -s backend/tests -v
./gradlew assembleDebug testDebugUnitTest lintDebug
```

В PowerShell используйте `.\gradlew.bat` вместо `./gradlew`. Для терминальной сборки `JAVA_HOME` должен указывать на JDK 17+, а `local.properties` — содержать локальный `sdk.dir` (Android Studio создаёт этот файл).

На Linux/macOS перед первым запуском выполните `chmod +x gradlew`.

HTTP-тесты создают временную базу и проверяют регистрацию, хеширование паролей, вход, изоляцию пользователей, срок сессии, каталог, цены из БД, корзину, оформление выбранного товара, одновременные запросы оформления и сохранение данных. Исходные Android example-тесты являются шаблонами и не покрывают пользовательские сценарии.
